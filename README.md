# LAST CROWN Studio

An English-language, anime-inspired 3D drama creation studio for LAST CROWN, designed to grow into a general-purpose story-to-screen workspace.

## Current browser foundation
- Create projects for LAST CROWN or original stories.
- Set language, genre and visual direction.
- Choose a project-wide visual direction: realistic 3D cinematic, stylised 3D, 2D anime, 3D anime, cinematic live-action realism, hand-drawn 2D, stop-motion, comic/graphic novel or hybrid mixed media. The selected direction is included in character and scene prompt guidance; it is a production brief, not a built-in renderer.
- Create and manage multiple episodes per project, each with its own saved script.
- Build a project-specific World Bible with 18 starting presets spanning ancient civilisations, African kingdoms, medieval and renaissance settings, colonial and traditional societies, industrial history, modern settings, near-future and cyberpunk cities, space-age worlds, post-apocalyptic settings, fantasy, mythology and steampunk. Customise era, geography, governance, settlements, architecture, interiors, landscape, climate, technology, transport, clothing, customs, food, languages, beliefs, economy, magic/science rules, conflict, palette, atmosphere and continuity rules. World settings are included in scene prompts, production packs and JSON backups.
- Create character profiles with appearance descriptions and fixed visual-continuity rules.
- Draft editable scene candidates from an episode script using a local rule-based parser; recognise explicit scene headings or propose paragraph-sized candidates, then select, edit and save approved scenes to the episode planner. This is deterministic assistance, not AI story understanding.
- Plan scenes per project and episode, including location, time, characters, action, shot framing, camera movement, lens choice, lighting/mood, character performance/animation movement, environment motion/effects, dialogue and visual prompts. The prompt builder adapts guidance to the selected visual style and preserves character continuity.
- Edit or delete saved scenes and download a Markdown scene plan.
- Organise JPG, PNG and WebP character references, scene references and general visuals in a per-project asset library, with descriptions, tags and direct links to saved character profiles and scene records. Linked reference thumbnails appear alongside the matching character or scene.
- Export and import a JSON backup containing projects, episodes, scripts, character profiles, scenes and image assets.
- Export an offline production prompt pack containing character continuity sheets and prompts for all saved scenes.\n- Build an episode production handoff pack combining the selected episode script, scene-by-scene breakdowns, character continuity, linked visual references, estimated runtime and a readiness checklist.
- Build a per-episode timeline from saved scenes, project images, audio clips and subtitle cues; adjust start times and durations, reorder items with touch-friendly controls, and save timeline metadata locally. This is a planning timeline. A basic local browser renderer can export a still-image/storyboard video with 0.6-second crossfades between adjacent visual segments, subtitle overlays and timeline audio scheduled against the resumed audio clock. Audio timeline items support per-track volume, stereo pan, fade-in and fade-out. Browser recording format depends on MediaRecorder support (typically WebM); an included, cached Termux/FFmpeg script converts WebM to MP4 locally on Android. For offline conversion, install FFmpeg in Termux before going offline; the conversion itself needs no network.\n- Record microphone audio or import audio files, classify clips as narration/dialogue/ambience/music, link clips to scenes, play and download clips locally, and create timed subtitle cues with SRT export. Audio blobs use browser IndexedDB and can be downloaded individually; subtitle cues are included in JSON backups.
- Use the Movie Theatre to import MP4/WebM files, play locally saved movies with native pause/seek/full-screen controls and playback speed, download or delete movies, and automatically add each completed Studio render to the selected episode's local movie library. Movie blobs use a separate IndexedDB database and are intentionally excluded from JSON backups; keep separate copies of important files. Actual playback depends on browser codec support and available device storage.
- Create lightweight 2D character-motion clips by compositing up to three independently controlled character images over a scene background, with individual idle, walk, run, entrance, float, fear/tremble, zoom and turn/reaction presets, independent size and placement. Preview and record a 16:9 WebM locally with the browser Canvas/MediaRecorder APIs; clips can be imported into Movie Theatre. This moves still character cut-outs only: it is not skeletal rigging, lip-sync, frame-by-frame animation, AI image-to-video or 3D animation.\n- Build multi-page comics from images in the Asset Library, add speech/thought/narration/sound text, edit panels, drag-and-drop panels within a page (with arrow controls for touch screens), set each panel to quarter/third/half/two-thirds/full-page width on a 12-column grid, apply page design, preview pages, control image crop/focus, choose page backgrounds and panel borders, and export a self-contained offline HTML comic for printing to PDF.

Deploy the `studio` folder to an HTTPS static host such as Cloudflare Pages (set the build output directory to `studio`). Open the deployed Studio once while online so its service worker can cache the app shell, manifest and Android converter script. On Android Chrome, use the browser menu → Install app / Add to Home screen. After the first successful cache, reopen the installed Studio with airplane mode enabled; the app shell and local editing/export workflows are designed to run offline. Direct `file://` opening does not support service-worker installation. See `studio/ANDROID-TESTING.md`.

**Storage:** project data and image assets are stored in the current browser's local storage. This is not cloud sync. The asset library limits images to 800 KB each and approximately 3 MB total; large image collections can exceed browser storage limits. Export backups regularly; clearing browser data can remove local data. Import replaces the current project, episode, script, character, scene and asset collections, so export a backup first. Backups containing images can be large.

## Not implemented yet
Actual AI text generation, character image generation, 3D asset creation, skeletal character rigging, lip-sync, frame-by-frame animation, advanced editing, advanced audio processing and direct cross-browser browser-side MP4 rendering remain roadmap items. A local Photo-to-Cinematic Video Studio is now implemented: upload up to 12 ordered photographs, reorder/remove them, apply camera motion (push, pull, pan or drift), choose cinematic colour atmosphere and crossfades, add opening/closing text and optional soundtrack, preview and export a 16:9 WebM locally. This creates a moving-camera photo montage, not AI-generated body movement, talking, fighting or new video frames. The Movie Theatre can import and play MP4/WebM files and retain completed Studio renders locally; it does not turn still images into fully animated scenes. Basic per-track volume, pan and fade controls are implemented. Android users can convert a WebM export to MP4 locally with the included Termux FFmpeg script in `studio/termux-webm-to-mp4.sh`; see `studio/ANDROID-TESTING.md`. Basic 0.6-second visual crossfades are implemented; they are not a full transition editor. The browser renderer uses MediaRecorder and does not guarantee direct MP4 output. Offline operation requires one initial online visit to cache the PWA shell and a previously installed FFmpeg package in Termux for local MP4 conversion. The Termux script provides a separate local Android conversion route; codec support depends on the installed FFmpeg build. Local audio recording/import and subtitle timing are implemented. Audio files are stored separately in IndexedDB and are not currently included in the JSON project backup; download important clips individually. The episode production pack is a local export/handoff document; the offline script-to-scene drafter proposes reviewable candidates but does not understand narrative like an AI model or render media. The new prompt builders are local templates: they assemble structured prompts from saved project data but do not call an AI model or generate media. Scene planning is implemented as a manual production-planning tool; it does not generate images or video. No AI provider is currently connected. The new photo compositor is a local canvas-based renderer; it does not call an image-to-video model.

## No-credit requirement
The built-in workflow must not depend on credit-metered AI generation APIs, paid generation subscriptions or hidden usage charges. Prompt construction and production-pack export run locally. Future image/video workflows must prioritise offline software and locally runnable open-source tools; optional remote services must never be required and must be clearly labelled if they impose quotas, accounts or costs.

## Android-first direction
Keep the interface lightweight. Heavy image/video models may need optional remote inference; clearly display provider availability, account requirements, quotas and costs. Do not describe quota-limited services as unlimited free generation.

## Local Python reference
The previously supplied `dark_crown_app.py` is a separate local application reference. It has not been merged into this repository; integration requires reconciling its runtime, model and storage paths.

The comic page preview also includes an accessible per-panel width slider. Drag its handle to resize a panel from 3/12 to 12/12 page width; the new size saves locally and is retained in HTML exports and JSON backups. On narrow screens, the same size is scaled to the six-column mobile grid.
